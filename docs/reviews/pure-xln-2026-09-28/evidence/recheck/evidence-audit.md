3. **Recovery rows have narrower status than architecture wording.** `recoverRuntime(..., rows?)` accepts absent rows; `runtime-2.test.ts:425-434` shows replay mismatch without rows after transport retirement, and success with exact frame `runtimeOutputs`. Thus optional rows are an incomplete recovery contract for that case, demonstrably, but no silent corruption was shown. `docs/wal.md:359-373` describes authoritative WAL inputs *and* durable outbox records; architecture's phrase “checkpoint plus WAL inputs and persisted ordered outbox rows” is a proposed seam, not proof that the pure `rows` argument corresponds exactly to canonical persisted data. 4. **Wallet malformed arrays are shared behavior, not rewrite incompatibility.** Pure `decodedEntries` treats any non-array as `[]` (`pure/xln.ts:32502-32510`), and old `tokenBalances`/`allowances` do the same (`core/jurisdiction/machine/event-normalizers-wallet.ts:19-68`). Pure `walletSnapshot` omits empty lists, strict block decoding calls the same normalizer, and `externalWalletJEvent` can apply its normalized snapshot. Static code establishes parser acceptance; no full watcher/peer delivery with a malformed on-chain event was reproduced. The adversarial file's P2 “concrete finding” and proposed pure-only fix should be retitled as a shared malformed-input policy question, with reachability unknown. The added primary adjudication already says this, but the contradictory original P2 wording remains.
5. **`ZERO_WORD` replacement is real; reachability remains unknown.** `installedAccount` substitutes `ZERO_WORD` for failures of `mapRoot(child.rebalancePolicy)` and `submittedAtRoot(body)` (`pure/xln.ts:27007-27008`), and `entityRootOf` consumes that leaf. State as a fail-soft corruption concern, not a demonstrated externally reachable consensus defect.
