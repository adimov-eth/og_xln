## Findings

1. **P1 — Invalid local J-history prune fails open.** `pruneFinalizedJHistory` returns `J_HISTORY_LOCAL_PRUNE_HEIGHT_INVALID` when finalized height exceeds scanned height (`pure/xln.ts:36644-36653`). `replicaJHistory` converts any error back to the original history (`:39020-39023`); both Entity input context (`:40075`) and committed history update (`:40475`) use it. The production `pruneFinalizedValidatorJHistory` throws for the same condition (`core/jurisdiction/machine/local-history/index.ts:568-580`) and Entity commit invokes it (`core/entity/consensus/j-prefix/prefix-round.ts:76-80`). This is a consensus/recovery boundary, so carrying the old history hides corrupt finality. Small correction: return `Result` through `entityContextFor` and `commitLocal` to frame application, or raise the typed halt at the Runtime boundary, preserving the code and evidence. Add one vector with finalized height greater than scanned height, then compare production and rewrite disposition.

2. **P1 — Compatibility claim has explicit WAL gaps.** The scenario differential says it does not compare WAL `frameHash`, because production includes `entityContextRefs` absent from this `StorageFrame`, and does not compare checkpoint frame `postStateHash` (`pure/diff/scenario.test.ts:1-15`). Yet `commitRuntimeFrame` claims parity with production `process + saveRuntimeFrame` (`pure/xln.ts:41772-41782`). Also, this function only returns a sealed value; it does not append/fsync WAL or dispatch effects, as required by `docs/core/rjea-architecture.md`. `core`, `frontend`, and `scripts` have zero imports from `pure/xln.ts`, and `pure/xln_run.ts:54-72` contains test signing including fake digest signatures for unknown addresses. Therefore current evidence supports a differential model, not a byte-compatible production Runtime or crash-safe replacement. Small correction: label the API/documentation as a frame planner; make production compatibility conditional on matching the excluded WAL bytes, integrating a single production WAL-before-effect host, and proving crash/replay/outbox with persisted rows. Do not add a parallel durable path.

3. **P2 — Recovery's default form depends on ambient routes and omits retained output evidence.** `recoverRuntime` allows `rows` to be absent (`pure/xln.ts:41863-41876`); then `replaySeed` returns live `routes` as supplied (`:41808-41828`). The existing test demonstrates that transport retirement between frames only reproduces with per-frame rows (`pure/diff/runtime-2.test.ts:425-434`). The optional form is useful for limited vectors but not a complete production recovery API: the canonical recovery source must be checkpoint plus WAL inputs and persisted ordered outbox rows, without consulting changed live route topology. Small correction: require recorded rows for the production recovery entry point; retain any rows-free helper only in test scope or clearly name its limited contract.

## Assessment

The conceptual Account → Entity → Runtime ownership is mostly clean. The principal architecture risk is confusing modeled frame sealing and selected differential parity with a production-integrated, byte-exact WAL boundary. Fix the J-history fail-open first; then establish the persisted production seam and close the explicit differential exclusions before claiming compatibility.
