## Five Structural Conclusions for Synthesis

1. **Kill single all-warning sheets (`p4/kernel-intent-firewall`):** Unconditional warnings caused `5/9` false rejections on a legitimate coffee checkout (`C5`).
2. **Separate outbound spend finality from held-collateral survival (`p1/kernel-sheet` Q4 bug):** Static `"locked amount can still be claimed"` on an outbound payment misled **`grok-4.7`, `gpt-6.2-astra`, and `claude-sonnet-4.5`** on Q4 (`C6`), whereas `sheet-spend`'s finality sentence achieved **`4/4` Frontier Q4 accuracy** (`C7`).
3. **Dispatch sheets by `deriveDelta` state-risk transition, never verb name (`p2` verb-dispatch seam):** Routing `'instant-swap` (`-1,000` locked -> `+1,005` unbacked, `deltaCreditLimit = 0`) by verb fooled `2/3` skimmers (`C3`); routing by `deriveDelta` (`outPeerCredit` / `peerCreditLimit` increase -> `'exposure`) achieved **`9/9 REJECT`** (`C4`).
4. **Render the concrete submitted transaction, never a static capability manifest (`claude-fable-5.2` `C7` catch):** Showing `send-routed, send-direct, open-account` on a single coffee payment caused `claude-fable-5.2` to rightly reject an unmentioned `open-account`. Checkout links (`invoice-link` in `p5`, `merchant-checkout` in `programs.scm`) must request payment only, and the sheet must render only the actual `EntityTx`s in the current submit.
5. **Keep `p3/desk-sign`'s per-lane batch lines, Hanko short-of-threshold proposal notice, and `maxSenderDebit - amount` fee ceiling.**
