## Причина и исправление

Проверка ордера завершилась `Out of memory`; следующий вход дал
`STORAGE_BOUNDED_CHUNK_BYTES_INVALID:490:4:9000`. Это сообщение не доказывало
повреждение сохранённых байтов: после исправления чтения тот же кошелёк
восстановился с проверками целостности.

`prepareBoundedStorageValueRows` передавал срезы общего ArrayBuffer. IndexedDB
клонирует весь backing buffer: каждый из **912** фрагментов Runtime frame **98902**
занимал **8,202,764 байта** вместо примерно 9 КБ. WAL SQLite занимал
**12,633,841,664 байта**. Это подтверждено read-only метаданными WebKit SQLite.

Теперь каждый новый фрагмент владеет компактным буфером. Чтение последовательно
копирует фрагменты в итоговый буфер вместо удержания всех больших backing buffers.
Ключи, логические байты, manifest и проверки length/count/digest сохранены.
В выборке последних 5000 записей новые фрагменты четырёх Runtime frames занимают
не более **9031 байта**, включая обёртку WebKit.
[Метаданные до/после](../output/ios-order-status-2026-09-13/storage-row-evidence.json).
Старые записи не переписывались; существующий файл базы не уменьшен.

## Проверки и открытые границы

- Регрессия structured clone: красная до исправления, зелёная после.
  Связанные codec/checkpoint/authority/native tests: **22 pass / 0 fail / 99 assertions**.
- Runtime types, целевой ESLint и frozen-core check прошли. Native host,
  Debug и Release собраны. Один успешный запуск существующего device wallet
  не доказывает BrainVault recovery на новом устройстве.
- Общий `bun run check` остаётся красным: `TEST_WORKSPACE_BUDGET_EXCEEDED`,
  лимит 53,687,091,200 байт. Лимит не повышался, чужие данные не удалялись.
- Запрос следующей котировки не завершился за запись; новую финансовую команду
  не подтверждали. Зафиксированы `RUNTIME_ACTIVITY_VIEW_GAP` и активная обработка
  истории. Точная цепочка блокировки котировки ещё не доказана. После диагностики
  приложение остановлено; [задержка на экране](../output/ios-order-status-2026-09-13/quote-history-delay.png).

## Экран отправки ордера

Команда возвращает `offerId` и `accountId`. SwiftUI показывает нейтральное
«исполнение ещё не подтверждено», идентификатор и кнопку открытия именно этого
ордера. Автоматическое чтение полной истории после отправки убрано по результату
неудачного теста. Успешное отображение итогового состояния нового ордера на
финальной сборке пока не проверено.

Следующий шаг: устранить измеренную задержку котировки/истории и записать полный
цикл нового ордера. Восстановление состояния важнее дальнейшей полировки дизайна.
