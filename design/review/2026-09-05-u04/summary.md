## Priority fixes by reviewer

### openrouter/google/gemini-flash-latest · desktop-dark · 633

The interface demonstrates rigorous financial state modeling and consistent technical restraint across views. Complex multi-tier balance concepts occasionally overwhelm standard flows, requiring clearer visual hierarchy.

- Clarify multi-tiered balance headers across screens by standardizing collateral vs credit color indicators.
- Add direct one-click cryptographic evidence bundle export from activity details and receipts.
- Reduce dead space on desktop settings, ownership, and manage screens via balanced multi-column cards.
- Introduce directional visual cues in the Move matrix to prevent source/target confusion.
- Separate testnet faucet utilities from production asset balances into a dedicated panel.

### openrouter/google/gemini-flash-latest · mobile-dark · 871

The xln mobile-dark interface establishes an exceptionally rigorous standard of financial transparency, making the subtle boundaries between on-chain reserves, collateralized accounts, and unsecured credit visually concrete through disciplined typography and absolute-scale bars. However, its uncompromising cryptographic honesty occasionally burdens casual payment and swap flows with protocol-level mechanics that should be tucked into progressive disclosures.

- Simplify Pay and Receive screens by truncating long entity hex IDs and separating invoice link sharing from protocol-level uri payloads.
- Collapse channel collateral configuration inside the Swap flow into an advanced drawer so retail users are not blocked by liquidity provisioning.
- Pin primary transaction action buttons (Pay, Move, Swap) to a fixed bottom action bar on mobile viewports to prevent cutoff.
- Harmonize the Move screen layout by replacing the double 3-column matrix with a streamlined Source-to-Destination stepper.
- Introduce an explicit 1-tap 'Collateralize' or 'Settle on-chain' shortcut wherever hub-promise counterparty risk is exposed.

### openrouter/qwen/qwen3.8-flash · desktop-dark · 741

A genuinely distinctive, premium self-custody wallet — the absolute-scale bars, sovereignty framing and provable-route pay flow are real differentiators that beat most crypto UIs on trust and visceral value. It is held back from 'strong' by terminology drift across screens, low-contrast microcopy, amount-bars that read as progress indicators, and several dead-end/empty states (swap, lending, ownership, activity-detail) that break the one-canonical-path feel on wide desktop.

- Unify vocabulary: one canonical label per concept ('owed to you', 'at risk', 'secured by collateral') reused verbatim on home, account, manage, sovereignty and desk — today the same number is 'hub promise', 'they owe you', 'promised by hubs' and 'at risk'.
- Stop using absolute-scale amount bars as row underlines in Activity and as micro-bars inside Move/Account cards; they read as loading/progress. Reserve bars for the balance/credit visualizations and add a one-time '1px=$1' legend.
- Raise the contrast floor on grey microcopy (send up to / receive up to / 'Show 1 empty' / palette descriptions / 'Depository may pull 0.00') and fix clipped text on the Sovereignty counterparty card.
- Repair the dead-end flows: swap (red error + disabled primary + credit button = no clear next step), lending (empty pool with no explanation), ownership (promised Register/Issue action missing). Each needs one recommended action and a 'why'.
- Fill empty desktop right-columns (activity-detail, ownership, manage bottom) with a default summary or next action, and tabular-align the Desk table numbers so Marcus can scan exposure at a glance.

### openrouter/deepseek/deepseek-v4-flash-vision-exp · desktop-dark · 806

The desktop-dark set is a cohesive, premium wallet with a genuinely differentiated 'one absolute scale' data language and a strong 'enforceable vs promised' trust framing that most competitors lack. The main drags are jargon density on the balance/composition legend, a thin invoicing story, and the complete absence of a mobile variant in the set, which keeps several personas (Maya, Sofia, Lena) from fully landing.

- Add an on-demand plain-language explainer (tooltip/inline 'What do these colors mean?') to the Home bar-scale legend so first-timers do not have to infer green/violet/purple semantics (helps Maya, Tomasz, Dmitri, Marcus).
- Turn Receive into a real invoice builder with required amount, currency, memo, invoice number, and a shareable proof-of-request link, so Sofia and Maya can send a professional invoice instead of a bare QR (04).
- Make the Swap 'Prepare to receive' collateral/credit chooser optional and non-blocking: default to credit, remove the red 'Prepare incoming capacity' warning, explain collateral only on expand (05).
- Add an explicit cross-chain Move/Bridge screen with an upfront fee and time-to-settle breakdown so Fatima sees the full cost and route before confirming (10, 05, 12).
- Reduce Desk density: give the lane table a minimum readable width and surface 'at risk' as a color-weighted in-cell bar instead of relying on the tiny legend, for Marcus and Ravi (16).

### openrouter/qwen/qwen3.8-flash · mobile-dark · 812

A genuinely premium, internally consistent dark UI whose biggest liability is that its most important idea — the green 'yours no matter what' vs violet 'hub promise' risk model — is explained only on the Sovereignty page while every other screen assumes the user already knows it.
